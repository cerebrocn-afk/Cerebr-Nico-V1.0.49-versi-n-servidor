## 4. El sandbox: por qué no arranca y por qué el preview queda colgado

Los 19 archivos que el modelo escribió son un híbrido imposible:

```
index.html      ← estático, SIN <div id="root">, carga <script src="script.js">
styles.css      ← y además src/styles.css, del mismo tamaño (2.093 bytes)  ← duplicado
package.json    ← "main": "index.html", "start": "live-server"
server.ts       ← express escuchando en PUERTO 3000 (el sandbox es 3500), fuera de "scripts"
tsconfig.json   ← rootDir ./src, include src/**/*  → server.ts en la raíz queda afuera
src/*.tsx       ← app React huérfana (index.tsx usa ReactDOM.render y react-dom NO está en dependencies)
src/tests/*.test.tsx × 4 ← tests de componentes que nunca se montan
```

Corrí la **función de decisión real** de v1.61.0 (`elegirViaPreview`) con esa huella exacta:

```
fuentes a transpilar: 12 (server.ts, src/constants.ts, … src/tests/Footer.test.tsx)
decisión: { via: "estatico-compilado", requiereInstalar: false, requiereCompilar: true }
entrada según html: script.js
```

De ahí salen tres cosas concretas:

1. **El log miente sobre la fase.** `requiereInstalar: false`, sin embargo el latido dice
   «instalando dependencias o levantando el servidor». El texto está *hardcodeado* en
   `src/components/RightSidebar.tsx:901` y no se deriva de la vía elegida.
2. **El vigía no tiene tope.** `RightSidebar.tsx:899-902` es un `setInterval` de 20 s que pitea
   indefinidamente mientras `await fetch("/api/sandbox/start")` no resuelve. El log del usuario
   muestra 9 latidos (hasta 180 s) y ningún estado final.
3. **Ésta es la causa del síntoma exacto que describiste** («el previsualizador no termina de
   cargar pero en localhost:3500 está la página»):
   - El `<iframe>` de `RightSidebar.tsx:1356-1363` **no tiene `onLoad` ni `onError`**: nada detecta
     que la carga del preview murió o se colgó.
   - El refresco de URL anti-caché depende de `setIframeKey`, que se dispara en la respuesta
     `online: true` del arranque y en la **primera** transición a vivo
     (`:520-523` y `:822-826`, ambas bajo `if (!everLiveRef.current)`).
   - Si el arranque nunca devolvió `online: true`, la carga muerta **nunca se reintenta**. El
     poll de 8 s sólo repone `iframeSrc` si está vacío, no si la última carga falló.
   - Resultado: el servidor termina por responder (por eso localhost:3500 muestra la página) y el
     previsualizador se queda para siempre en la request vieja.

El anti-caché que había quedado pendiente sí está cableado (`:1359`,
`urlConAntiCache(iframeSrc || SANDBOX_URL, iframeKey)`). Lo que falta no es el token: es **saber
que el load falló**.
